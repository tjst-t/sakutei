# Sakutei 設計書 v3.0 変更一覧(CHANGELOG)

対象:`sakutei-design-v2.6.md` → `sakutei-design-v3.0.md`。改訂日 2026-07-22。

## 宣言:v3.0 は v2.6 と内容等価の全面再構成である

**v3.0 は新しい設計判断を一切導入していない。** v2.2 から v2.6 に至る五世代のパッチ的改訂
(レビュー指摘への逐次追記)で、章立てが「追記された順」に堆積し、同じ決定が複数箇所に分散・
重複する状態になっていた。v3.0 はこれを、確定した**八部・29節構成**へ織り込み直した**全面再構成
(再編集)**である。

- **設計判断(何を作り・何を委譲し・どう安全に収束させるか)は v2.6 と等価**。差分は構成・重複解消・
  クロス参照・体裁に閉じる。
- v2.2〜v2.6 の各改訂で「何を・なぜ変えたか」の履歴は、それぞれの `CHANGELOG-v2.x.md` と旧版ファイルを
  参照する。v3.0 はそれらの履歴を**再説明しない**(織り込んだ結果だけを持つ)。
- 旧版(`sakutei-design-v2.2.md`〜`sakutei-design-v2.6.md`)は歴史として保持し、編集しない。

## v3.0 再構成で行った軽微な調整

内容(設計判断)を変えず、統合・重複解消・参照修正・体裁統一のみを行った。以下がその全一覧である。

### 修正したクロス参照(誤参照の是正)

v2.2〜v2.6 では converging / settle / oscillating の検知が安全機構節(旧 §10.4/§14 系)に置かれていたが、
v3.0 では「多周期収束」(§11)に移動した。これに伴い、本文で converging を **§14** と参照していた 4 箇所を
正しい **§11 系**へ修正した。

| 箇所(v3.0) | 修正前 | 修正後 | 対象概念 |
|---|---|---|---|
| §4.5 Observation(converging の説明) | §14 | **§11** | converging(綱引きになる) |
| §4.5 Observation(oscillating の導出) | §14 | **§11.3** | oscillating(履歴から導出) |
| §5.7 BulkObserve(走査窓内遷移の吸収) | §14 | **§11.1** | converging / settle 自傷猶予 |
| §19.9 waiting-allocation 縮退 | §14 | **§11.1** | converging に類似した状態 |

その他の §N 参照は確定目次と全数突き合わせ、整合を確認した。とくに subsection 参照(§N.M)は全件が実在の
小節見出しに解決することを確認済みである(ready_condition=§11.2、fencing=§15.2/§17、承認ゲート型=§6.4/
§14.4、BulkObserve 契約=§5.7、早期収束=§8.6、planned_change=§13.3、プロファイル=§14.5、S2-free=§17.5、
停止影響表=§22.4、DR=§25、合成検証 canary=§26.5、CLI 全 verb=§26.6)。

### 圧縮した重複(主たる置き場を残し、他方を1行+参照に)

部をまたいで同一の決定がフル記述されていた 2 件を、主たる置き場に一本化し、他方を要約 + 参照に圧縮した。

| 重複していた決定 | 主たる置き場(残した) | 圧縮した側 | 圧縮内容 |
|---|---|---|---|
| capacity gate(YAML 宣言 + halt セマンティクス +「是正は reconciler の外」の分担) | **§13.4**(変更予算) | §11.4(多周期収束) | フル記述(YAML・分担説明)を削り、「多周期収束における適用点」+「宣言形・halt・分担は §13.4 を正とする」の要約に圧縮 |
| 観測不能資産の階級(observability:none / ledger_only / last_verified の型定義 + prune 巻き添え遮断 + 時間ベース検証) | **§5.8**(Provider 抽象) | §24.6(ブラウンフィールド) | 型定義 YAML と共通 2 箇条(Read/Diff/Apply 対象外・prune 除外)を削り、「型定義は §5.8 を正とする」+ ブラウンフィールド固有の適用文脈(last_verified 鮮度述語・v1a/v1b スライス)に圧縮 |

なお、承認ゲートのフロー(§6.4 / §14.4 / §26.6)と CLI verb(§1.5 位置づけ / §26.6 全 verb)は、
プリミティブ定義・安全機構・リファレンスという**異なる読者文脈で自己完結する意図的な再掲**であり、
相互参照が既に張られているため圧縮対象としない(フル記述の重複ではなく、短い定型 + 相互参照)。

### 体裁の統一

- **見出しレベル**:部 = H1(`#`)、節(§N)= H2(`##`)、小節(§N.M)= H3(`###`)に統一。
- **文体**:全編である調。
- **表記ゆれ**:早期収束パス / トリガ収束は「早期収束パス(トリガ収束)」、claim-as-intent 表記を統一。
- **コードブロック**:言語指定(go / yaml)を維持。
- **括弧幅**:散文の括弧は**全角(（）)に統一**した(コードブロック・インラインコードは半角を維持)。従来は部境界で全角/半角が切り替わっていた(執筆分担の痕跡)。
- **識別子表記**:型・ハッシュを指す識別子は underscore 形に統一(`provider_version` / `intent_revision` / `rendered_revision`)。散文中の空白形を除去した。
- **冒頭**:タイトル・改訂日・位置づけ・全体目次(部・節・小節の一覧)を追加した。
