## 所見

1. **「衛星の停止は、変化を止めるが、維持を止めない」(§16.7)が今回の最有効打** — 04/06/07/11/20 の 5 構成で衛星可用性懸念を一掃した。「定常収束は衛星コールゼロ、QPS は churn 比例」という算術は、早期収束パス(v2.4)が生んだ副作用への正面回答として機能した。
2. **S2-free シャード(§12.5)は 06/14 の 2 構成で「v2 機能(RemoteExecutor)が必要」という前提自体を消した** — v2.4 の claim-as-intent と同じ「前提の付け替え」型の解決。分散型ユースケースで残る v2 依存は動的リバランスと lease 縮退の精緻化のみ。
3. **改訂が新しい懸念を生まなかった最初のラウンド** — v2.3→v2.4 はそれぞれ新懸念(累積予算の衝突、衛星 QPS)を生んだが、v2.5 の 3 テーマは既存機構への接続(managed 除外・converging/settle・fencing 再利用)で閉じており、7 構成の再判定で新規の設計ギャップ指摘はゼロだった。設計が収斂しつつあるシグナル。
4. **残る既知課題(据え置き)** — 多相 Task・自動段階ロールアウト/canary・credential-broker・DBSource(いずれも v2 スライス)、大量正当作業と累積予算の衝突(11/13)、4-eyes(17)。これらは「未設計」ではなく「実装順序」の問題として整理済み。
