# 対象構成06(再評価): マルチサイト企業インフラ(3DC + DR)への Sakutei 適用性 — v2.5

**新判定:○(条件付き成立)。DR の平常経路(定常収束・サイト分割・停止影響の言語化)が v2.5 で確定し、△を据え置かせていた最後の芯(allocator 生存が RTO 直結・福岡遠隔管理・停止影響の非仕様)が実装到達または明示的に不要化された。純粋に残るのは「東京全損時の PR 承認・署名の代替経路(runbook)」と「fencing 世代のクロスサイト同期複製(v2)」の 2 点のみ。**
**判定推移:v2.2 △(大幅な拡張が必要)→ v2.3 △(思想の空白→実装待ちへ前進)→ v2.4 △(サイトシャーディング本体が v1b で成立・○直前)→ v2.5 ○(定常収束の衛星非依存・S2-free シャード・停止影響表で△の芯が外れ、条件付き成立)**

v2.4 で「○ 直前の △」まで来ていた本構成の残置は、(1) 大阪 allocator 生存が RTO 直結、(2) 福岡遠隔管理に RemoteExecutor が要る、(3) fencing/S2 の同期複製、(4) DR 中の PR 承認経路——の 4 点だった。v2.5 の 3 テーマ(衛星の天井・BulkObserve 一貫性・claim git 配布/S2-free)は、(1) を原則で、(2) を新階級で構造的に解消し、(3)(4) を「変化の可用性だけの問題」に格下げした。判定を △ から ○ へ進める。

## 2. 判定を ○ に進める理由(△ の芯が「実装スケジュール上の欠落」から「runbook の 1 行」へ縮小)

v2.4 の判定を △ に据え置かせていたのは「(f) 残る v2 塊=福岡遠隔管理・lease 縮退・S2 同期複製」と「新課題3=allocator 生存が RTO 直結」だった。v2.5 はこの両方を実質的に外した。

- **allocator 生存が RTO 直結という論点が原則で溶けた(CHG-G1/G3)**。DR の本質は「東京 scope の**既存**資産を大阪が維持収束で引き受ける」ことであり、既存資産の Lookup は Release まで不変=衛星ゼロで回る。allocator が要るのは DR 後の**新規作成**だけで、それすら `waiting-allocation` で安全に遅延する(halt でも事故でもない)。→ **RTO を律速するのは allocator 生存ではなく「維持収束が回るか」に変わり、後者は衛星非依存**。これは本構成の RTO 議論の重心を根本から動かす。
- **福岡遠隔管理が S2-free claim で 14 と同論法で消えた(CHG-I3)**。「中央から福岡をリモート収束する→RemoteExecutor が要る→v2」という v2.4 の連鎖が、「福岡に段0-minimal + `--claim {site: fukuoka}` を置き自ホスト LocalExecutor で自律収束」に組み替わる。S2-free 化で福岡ホスト全損も無害(再イメージ→pull→収束)。福岡は Resource 収束のみで足りる可視化用途なので、S2-free の「Task/Workflow は中央 claim 側で」という制約(§12.5)にも抵触しない。→ **v2.4 の残置 3 点のうち「福岡遠隔管理」が完全に不要化**。
- **サイト間採番依存がプール分割 by claim で切れた(CHG-G5)**。disjoint レンジの静的宣言で各サイトが独立払い出し。分断中も各サイトは自レンジで払い出せ、中央依存は ASN 等のグローバル空間のみに縮む。これは v2.3 の成立条件 (c) の実装到達であり、DR で大阪が「東京 scope 用の VLAN/IP を大阪プールから」払い出せることを意味する。
- **停止影響表(§19.9)が DR 運用の言語を与えた(CHG-G4)**。「サイト分断で何が止まるか」を推測でなく仕様で答えられる。v1 では「衛星が全部落ちても維持収束は回る」が保証で、これは DR/分断常態(§6.2 割り切りへの抵触)を「協調破綻」から「新規変化だけが待つ」へ格下げした v2.4 CHG-F4 の帰結を、衛星面でも定量化したもの。

**結論**:v2.3 で「設計裏付けは揃うが実装が v2」だった成立条件のうち、v2.4 で (c)(f) の大半が v1b 到達し、v2.5 で**残る (f) の福岡遠隔管理が不要化・allocator HA/プール分割が v1b 実装到達**した。判定コードを **○(条件付き成立)** に進める。◎(思想を曲げず完全自動 DR)に至れない構造的理由(観測 state レス・shared-nothing・DR 判定を人間に委ねる)は不変だが、それは仕様の意図であって欠陥ではない。

## 3. 残存(○ にしてなお残る条件・v2 塊)

1. **DR 中の PR 承認・署名経路の東京依存(R5・最後の実質障壁)**。claim 変更を PR に一本化した設計の代償として、**その 1 経路が切れると DR 操作そのものが止まる**。§26.3 C(Sync Mode commit 主体・署名)未決のまま。**runbook に「東京全損時の claim 変更 PR の代替承認者(大阪側)・オフライン署名鍵・fencing 世代の手動発行」を明記**する必要が残る。これは設計の欠落でなく運用設計事項だが、○の成立に必須。
2. **fencing 世代のクロスサイト同期複製は v2(R4)**。「古い東京 writer を fence する」ための世代一貫は S2 複製の一部として v2 残置。quorum ストアを東京集中に置くと分断中に fence 更新不可——**設置サイト選択(quorum を東京単独に置かない)が本構成固有の判断**として残る。v2.4 から規模は縮小したが消えていない。
3. **DR 後の新規大量作成は allocator 復帰まで `waiting-allocation` で遅延(R1')**。事故ではなく UX 遅延だが、DR 直後に「全く新しい大量リソースを即座に作る」要件があるなら、大阪 allocator の HA 投資(§16.5 active/standby)が RTO 見積に効く。既存資産の引き継ぎには効かない点を RTO 定義で分離すること。
4. **AD/DNS のマルチマスタ整合は収束対象外(不変)**。§20.1 不変。「サービス存在・起動」までしか保証しない。主目的の一部であり続けるため、Sakutei に期待しない切り分けの明示は前回同様に必要。

## 4. この構成で成立させるための条件(v2.5 更新版)

- **(a) 各サイトに独立 claim デーモン + サイト段0**:東京/大阪は標準段0、**福岡は段0-minimal + S2-free claim**(§12.5・CHG-I3)。各デーモンは `intent/<site>/` の sparse checkout で自 claim 分 + `intent/platform/` のみ取得(§12.5)。**v1b で実装到達**。
- **(b) allocator HA 最小形 + プール分割 by claim**:段0 VM-HA 上 active/standby + fencing(§16.5)。サイト固有 VLAN/IP は disjoint レンジ宣言で各サイト独立払い出し、ASN 等グローバル空間のみ単一権威(分断中 reserve 不可を許容)。**定常収束は allocator 断でも Lookup キャッシュで回る**(§16.7)。**v1b 実装到達**。
- **(c) git の正を DC 外化 + ミラー中継(2 拠点)+ DR 承認経路の runbook 化**:読み取りはローカルミラーで全断耐性(§12.5 ミラー)。**追加で東京全損時の PR 承認・署名の代替を runbook 明記(残存1)**——§26.3 C 決定が前提。
- **(d) DR = 再シャード Workflow(承認ゲート付き最小 Workflow)**:「大阪 claim に東京 scope を足す PR → fencing 世代更新」(§12.4)。`primary_confirmed_lost` は承認ゲートの人間入力、fencing 世代は S2 更新。最小 Workflow(v1.5)で表現可能。**自動判定は不可(§18 不変)**。
- **(e) AD/DNS のレプリ整合は Sakutei 外・シャード間は「現実を介した Observe gate」**(CHG-F4 で確定・不変)。
- **(f・大幅縮小) 残る v2 は fencing 世代の同期複製のみ**:福岡遠隔管理は S2-free claim で不要化(残置解消)、lease 縮退は fencing+`unknown≠absent`+rate-limit halt で当面代替。**quorum 設置サイト選択が本構成固有の残判断**(残存2)。

**総括**:v2.5 は「衛星の停止は変化を止めるが維持を止めない」を設計保証に格上げすることで、本構成の DR 議論の重心を「衛星生存」から「維持収束が回るか(=衛星非依存)」へ動かした。加えて S2-free シャードが福岡遠隔管理を(14 と同論法で)不要化し、プール分割 by claim がサイト間採番依存を切り、停止影響表が分断時の挙動を仕様化した。v2.4 で「○ 直前」だった△の芯——福岡遠隔管理・allocator が RTO 直結——が外れ、**判定は ○(条件付き成立)に到達する**。○にしてなお残る最後の障壁は技術でなく **runbook 1 行(東京全損時の PR 承認・署名の代替経路)** と **quorum 設置サイトの選択**であり、いずれも導入設計の範囲で閉じる。
