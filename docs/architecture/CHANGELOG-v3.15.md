# Sakutei 設計書 v3.15 変更一覧（CHANGELOG）

対象: v3.14 → v3.15。改訂日 2026-10-22。骨格（§1〜§29 の機構）と設計判断（原則・機構）は不変。本改訂は **Redfish の BMC provider（Backlog #48）の範囲と決まり**を §29.1 に書き足すだけの小改訂である。

形式: **変更ID / 対応 / 章 / 変更内容 / 設計判断の理由**。対応の `#nn` は Backlog の項目番号。

---

## CHG-01 — Redfish だけで作り、IPMI は持たない

- **対応**: #48（2026-10-22 人が決定）
- **章**: §29.1
- **変更内容**: 物理（電源/BMC）層の最初の provider は Redfish だけで作る。IPMI を予備に持たない。
- **理由**: IPMI の電源状態は on / off だけで、正常停止の途中（PoweringOff）が見えない。Converging を返せないと、止まりかけているサーバに同じ操作を重ねる。IPMI だけの古い BMC が要るなら、別の provider として足す。

## CHG-02 — 起動先の上書きで宣言できるのは Continuous と Disabled だけ

- **対応**: #48
- **章**: §29.1
- **変更内容**: `boot_enabled: Once` は計画の時点でエラーにする。Once は将来 Task 側で扱う。
- **理由**: Once は 1 回起動すると BMC が Disabled・None に戻す。あるべき状態として宣言すると、戻ったことをずれと見なして設定し続ける。一度きりの操作は Task の領分である。

## CHG-03 — 正常停止が効かないときの ForceOff は宣言したときだけ・予算に数える

- **対応**: #48
- **章**: §29.1（§13・§22.3）
- **変更内容**: 既定（`power_off: graceful`）では ForceOff に進まず、ずれの level が続いて stuck に上がることで知らせる。`power_off: graceful_then_force` と `force_after` を宣言したときだけ ForceOff に進み、ForceOff は破壊的な操作として予算に数える。GracefulShutdown を送った時刻は S3 に持つ。
- **理由**: 強制停止はデータを失いうる。ゲストが止まらない理由（更新中・ハング）を Sakutei は見分けられないので、既定は人に知らせるところで止める。宣言で許したときも、予算で一度に止める台数を抑える。

## CHG-04 — 仮想メディアを最初から含める

- **対応**: #48
- **章**: §29.1
- **変更内容**: ノードごとの仮想メディア（CD）を、`image` を宣言して Insert / Eject で収束するリソースとして含める。破壊的な操作には数えない。
- **理由**: qemu-bmc v0.8.0 で、電源オフ中も残り Inserted・Image を読み返せる形になり、収束の対象として扱える。OS 導入の手順（Task / Workflow）で使う道具を先に用意しておく。

## 見送り

- **IPMI provider**: 要る BMC が出てから。
- **再起動の宣言**: 一度きりの操作なので Task の領分（v1.5 以降の多相 Task）。
- **セッション認証（X-Auth-Token）**: Basic 認証で足りる間は持たない。
