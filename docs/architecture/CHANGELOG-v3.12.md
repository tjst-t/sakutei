## CHG-01 — dnszone は、管理するレコードを書き換えた Apply のときだけ SOA のシリアルを上げる（既定。設定で止められる）

- **対応**: #70（2026-10-21 人が決定）
- **章**: §29.1
- **変更内容**:
  - 管理するレコードを実際に書き換えた Apply（Create / Update / Delete でファイルの中身が変わったとき）だけ、同じ書き込みで SOA のシリアルを上げる。
  - 新しい値は `YYYYMMDDnn`（日付は UTC）で、「今日の `YYYYMMDD00`」と「今の値 + 1」の大きいほう。今の値より必ず大きくなる。32 ビットの上限を超えるときは上げずに Apply を PermanentError で止める。
  - SOA のそれ以外の欄は引き続き管理の外。シリアルは Diff の対象にしない。ゾーンに SOA が無ければ何もしない。
  - 既定は上げる（`soa_serial: bump`）。`soa_serial: keep`（CLI は `--zone-soa-serial keep`）で上げないようにできる。
- **理由**: SOA を管理の外にしたまま（v1a）だと、レコードを書き換えてもシリアルが変わらず、セカンダリへの転送やサーバの再読み込みが起きない。収束したはずの値が DNS の答えに出ないので、「触っていないのに戻る」が実際の DNS で成り立たない。シリアルの上げ忘れは手作業のゾーン編集でいちばん多い事故でもある。一方、ゾーンを Sakutei 以外も書く環境ではシリアルの採番がぶつかりうるので、止める設定を残した。シリアルを下げることはセカンダリを壊すので、上げ方は「今の値より必ず大きい」を保証する形にした。

## 見送り

- **SOA を丸ごと管理する（MNAME・refresh なども intent に書く）**: 管理の境界を広げる設計変更になる。今回の目的（変更を DNS に行き渡らせる）にはシリアルだけで足りる。
- **1 周で 1 回だけ上げる**: provider の Apply は 1 操作ずつで、周の切れ目を provider に知らせる口が無い。複数回上がっても単調増加は保たれるので、口を足すほどの理由が無い。
