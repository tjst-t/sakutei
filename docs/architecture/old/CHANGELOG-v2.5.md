## G. テーマ①:衛星の天井 —「衛星の停止は、変化を止めるが、維持を止めない」

早期収束(採番が UX 直結・§6.8)と claim 分割(全シャードが共有衛星に依存・§12.4/§12.5)の合流点として
特定された「allocator/Vault の QPS・可用性が次の天井」(04/06/07/11/20 の共通指摘)を、部品追加だけでなく
**原則**で塞ぐ。

### CHG-G1 — 原則の明文化「衛星の停止は、変化を止めるが、維持を止めない」を §16.7 に新設
- **章**:§16.7(新設)、§6.5(S3 表に allocation Lookup キャッシュを追加)、冒頭「v2.4 からの主な変更」
- **要約**:定常状態の収束ループは**衛星コールゼロで回る**ことを設計保証にする。**割当事実は Release まで
  不変**なので `Lookup` 結果はシャードローカルに**無期限キャッシュ可**(無効化は自分の Release のみ)。観測
  state レス原則との整合を明記——割当事実は「観測」ではなく「自分が確定させた事実」なので保持してよく、
  **S2 ではなく再取得可能なキャッシュ=S3 扱い**(喪失時は allocator に Lookup し直すだけ)。secret は既存の
  last-resolved 保持 + TTL キャッシュ(§14.2/§7.4)を維持。
- **理由**:「allocator/Vault がスケール天井」という論点を、HA・キャッシュという部品でなく**原則**で塞ぐ。
  維持(定常収束)と変化(新規採番)を分離し、衛星の可用性が守るのは変化だけであることを設計保証に格上げする。
- **応答**:04/06/07/11/20(共通指摘)。

### CHG-G2 — QPS 算術の第一級化(§16.7)
- **章**:§16.7、§12.2(スケール要約表に「衛星は Observe 天井の算術に乗らない」注記を追加)
- **要約**:allocator QPS は**フリート規模ではなく変更レート(churn)に比例**する。例:10,000 リソース・日次
  churn 1% = 新規採番 ~100 件/日 ≒ 無負荷(定常 9,900 は Lookup キャッシュヒットで allocator に触れない)。
  早期収束のバースト = ポータル申請レートで上限される。allocator の sizing は「churn + ポータル申請ピーク」で
  行う。「allocator がスケール天井」という誤解を数値で潰す。
- **理由**:共有衛星が次の天井という指摘を、実務上の sizing 根拠(churn ベース)で緩める。フリート規模に比例
  するという誤った直観を算術で明示的に否定する。
- **応答**:04/07/11/20。

### CHG-G3 — 衛星停止時の縮退(waiting-allocation)を §16.8 に新設
- **章**:§16.8(新設)
- **要約**:allocator 停止 → **新規採番が必要なリソースだけが `waiting-allocation` 状態**(converging 類似・
  エラーでも halt でもなく下流 skip のみ)。既存リソースの収束は Lookup キャッシュで継続。Release は元々
  非対称・遅延可なので停止中は安全に保留。早期収束パスの新規払い出しヒントは**キュー保持し定期周期へ縮退**
  (allocator 復帰後の周期で払い出され waiting-allocation が解ける)。
- **理由**:「衛星停止 = 全停止」ではないことを状態遷移として型で表現する。エラー/halt でなく converging 類似の
  一時状態にすることで、既存の失敗伝播機構(下流 skip・§6.3)を再利用できる。
- **応答**:07/20。

### CHG-G4 — 衛星停止影響表を §19.9 に新設
- **章**:§19.9(新設)
- **要約**:各衛星の停止が「何を止め、何を止めないか」の表。allocator = 新規採番リソースの作成のみ停止 /
  Vault = secret を持つ Apply のみ alert-only 縮退(Observe 継続・§19.7 と接続)/ credential-broker(v2)=
  Observe 全停止 = 全盲(だから可用性要件が最上位・§15.1 と接続)。**v1 では broker が無いため、衛星が全部
  落ちても定常収束は回り続ける**ことを §16.7 の v1 帰結として明記。
- **理由**:衛星ごとの可用性要件の非対称(broker 断 > Vault 断 > allocator 断)を1枚の表で読めるようにし、
  「どの衛星に HA 投資すべきか」の判断根拠にする。
- **応答**:04/06/07/11/20。

### CHG-G5 — allocator HA 最小形 + プール分割 by claim を §16.5 に追記
- **章**:§16.5(interface 節に追記)
- **要約**:v1b の自作 SQLite 実装は**段0 VM-HA 上に置き active/standby + fencing token(§12.3 再利用)**。
  可用性目標は reconciler 以上。割当記録は **quorum ストア(S2 と同じ置き場)への相乗り可**。**プール分割 by
  claim**:サイト/シャード固有プールは **intent でレンジを disjoint に分割宣言**(例:site-a は VLAN 100-199)
  → シャードは自分のレンジだけを自 allocator(またはローカルインスタンス)で管理でき、中央 allocator への
  依存は「全シャード共有プール」だけに縮む。**実行時のレンジ委譲プロトコルは作らない**(宣言で足りる)。
- **理由**:HA は「変化の可用性」のための投資であり「維持の可用性」のためではない(§16.7)ことを明記した上で、
  中央 allocator への依存自体を claim 軸のプール分割で構造的に縮める。動的調停でなく静的宣言(claim-as-intent
  と同思想)で分割境界を固定する。
- **応答**:06/07(サイト分割)、04/11。

### CHG-G6 — エッジの資格局所性を §15.7 に新設
- **章**:§15.7(新設)
- **要約**:店舗/エッジ claim の write 資格は**店舗ローカル file SecretBackend に常駐**(その店舗の機器分
  のみ=爆発半径は当該店舗に閉じる)。WAN 断中も自律収束が回り、再接続時に中央から rotation 収束。「資格常駐の
  破壊力 vs 自己修復」のトレードオフをこの局所化で決着させる。broker(v2)導入後は層B 相当の暫定として JIT
  発行へ移行。
- **理由**:第3ラウンド 14 の残存ギャップ G3(資格常駐の破壊力 vs 自己修復)への直接応答。局所常駐(当該店舗
  にしか及ばない)+ 中央 rotate 収束で両立させる。§16.7 の「維持は衛星ゼロで回る」を資格面に適用した形。
- **応答**:14(残存ギャップ G3)。

## H. テーマ②:BulkObserve の一貫性契約(§5.8 新設)

v2.4 で走査窓内スナップショット非一貫(DRS 稼働中の PropertyCollector、AWS Describe 結果整合 + ページング)が
指摘された(04/19)。SDK 契約として明文化する。

### CHG-H1 — BulkObserve の一貫性契約を §5.8 に新設
- **章**:§5.8(新設)、§5.7(末尾に §5.8 を正とする旨を追記)、§4.2(`Observation` に `ObservedAt`
  フィールド追加)
- **要約**:SDK 契約として次を明文化。**(1) 非アトミックスナップショット宣言**:結果は「走査窓内のある時点の
  各リソース」であり全体の一貫スナップショットではない。level-triggered が次周期で自己修正するため、これは
  正しさの問題ではなく揺らぎの問題。**(2) complete-or-error**:ページングは完走するかエラーを返す(List §8.6-a
  と同じ規律。部分結果の黙示返却は禁止)。**(3) 型分離**:BulkObserve は Observe 専用で **prune の根拠には
  使えない**(prune は Lister.List + §8.6 完全性検証)。SDK が誤用を型レベルで防ぐ。**(4) 走査窓内遷移の吸収**:
  DRS 移動等は managed fields 除外が、一時的不整合は converging/settle(Tier2)が吸収する既存機構への接続を
  明記。**(5) SDK 等価性テスト標準装備**:fake provider 上で `BulkObserve(scope) ≡ {Read(id) ∀id}` を SDK
  テストハーネスに標準装備(「完全」階級 + bulk を名乗る条件)。**(6) `observed_at` 刻印**:各 Observation に
  観測時刻を刻み、bulk 結果は当該周期でのみ使用(周期をまたぐ再利用は観測 state レスに反するため禁止)。
- **理由**:バルク走査窓の非一貫を「正しさの問題」と誤解すると、prune への流用・周期越え再利用で事故る。
  型分離と等価性テストで誤用を CI・型レベルで塞ぎ、揺らぎは既存の converging/settle・毎周再観測に吸収させる。
- **応答**:04/19。

## I. テーマ③:claim 方式の git 配布と S2-free シャード(§12.5 新設)

v2.4 で 300 拠点 git pull トラフィックと店舗ローカル S2 耐久性が指摘された(14)。

### CHG-I1 — リポジトリレイアウト規約 + sparse checkout を §12.5 に新設
- **章**:§12.5(新設)、§12.2(スケール要約表の地理分散行に §12.5 を追記)
- **要約**:claim でシャーディングする場合、intent リポジトリは **`intent/<scope>/...` のパス接頭辞規約**に従う
  (claim ↔ パスの対応を機械可能に)。各シャードは **sparse checkout / partial clone** で「自 claim 分 +
  共有 platform 参照分」のみ取得。§12.4 の「全 intent を pull」を否定せず**トラフィック最適化**として精緻化
  (正しさは「自 claim にマッチする scope だけ収束」で担保)。
- **理由**:300 拠点で全 intent pull は非現実的。claim ↔ パスを機械対応させ、fetch 範囲を宣言から導出する。
- **応答**:14。

### CHG-I2 — ミラー中継層を §12.5 に追加
- **章**:§12.5
- **要約**:多拠点は読み取り専用 git ミラー(状態を持たない中継。中央 2 拠点程度)から **jitter 付き
  ポーリング**で pull。webhook(早期収束ヒント)は NAT 越え不可の拠点ではポーリングが代替(level ループが
  保証なのでヒント欠落は遅延のみ)。**算術**:300 拠点 × sparse fetch/60s = 5 fetch/s はミラー1対で余裕。
- **理由**:中央 git 本体への直接負荷を状態レスなミラー数(2)に固定し、NAT/WAN 断環境でもポーリングで
  level ループが回ることを保証する。
- **応答**:14。

### CHG-I3 — S2-free シャード階級の新設を §12.5 に追加
- **章**:§12.5
- **要約**:エッジ/店舗 claim は **Resource 収束のみ**を担い**ローカル S2 を持たない**階級(デーモンホスト
  全損でも失うものゼロ。再イメージ→pull→収束で完全復旧)。Task/Workflow が必要な操作は (a) 中央 claim 側で
  実行するか (b) 完了マーカーを現実側に置くパターン(§20 schema_migrations と同型)で表現。
- **理由**:段0-minimal(quorum なし)の店舗ローカル S2 耐久性問題を、「何も覚えないから何も失わない」階級で
  構造的に回避する。§19.8 の段0-minimal と最も相性がよい。
- **応答**:14。

### CHG-I4 — 開店/閉店 = claim 変更 PR による所有権ハンドオフを §12.5 に追加
- **章**:§12.5
- **要約**:新店舗 scope は最初は中央のプロビジョニング claim 下で構築(中央が S2 付きで Task/Workflow 実行)、
  安定後に claim 変更 PR で店舗デーモン(S2-free)へ引き渡す(閉店は逆順)。§12.4 の再シャード Workflow
  (drain→claim 変更 PR→fencing 世代更新)の具体適用。
- **理由**:プロビジョニング(手続き的・S2 が要る)と定常収束(Resource のみ・S2-free)を claim 境界で分離。
  開店/閉店を PR + fencing で監査・レビュー対象にし、二重所有を fencing で検知する。
- **応答**:14。

## 本改訂で採用しなかった選択肢(見送り理由つき)

- **実行時のレンジ委譲プロトコル(allocator の動的プール分割)**:**見送り**(CHG-G5)。プール分割は intent の
  disjoint レンジ宣言(claim-as-intent と同思想)で足りる。動的調停機構は割当表(S2)とその可用性を新たな
  中心依存にするため、静的宣言で分割境界を固定する。
- **割当 Lookup キャッシュの永続化(S2 化)**:**見送り**(CHG-G1)。割当事実は再取得可能(allocator に
  Lookup し直すだけ)なので S3(インメモリ・非永続)で足りる。永続化すると観測 state レスの看板に近づく上、
  喪失時の縮退が「一度問い直す」だけなので S2 の重い保証は不要。
- **BulkObserve を prune の根拠に流用(1コールで List も兼ねる)**:**見送り/棄却**(CHG-H1)。prune の安全性は
  §8.6 の List 完全性検証に依存し、Observe の高速化とは要件が異なる。型を分離し SDK で誤用を塞ぐ。
- **BulkObserve 結果の周期越え再利用**:**禁止**(CHG-H1)。古いバルク結果を「現在状態」として次周期に持ち越す
  ことは観測 state の再導入。`observed_at` 刻印で検知・拒否する。
- **中央集約の全店舗資格配布**:**見送り**(CHG-G6)。店舗ローカルに当該店舗分のみ局所常駐させ、爆発半径を
  当該店舗に閉じる。中央の全資格を配ると 1 店舗の漏洩が全店舗に及ぶ。
