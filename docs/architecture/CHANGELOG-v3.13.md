## CHG-01 — Sakutei 自身の prune で消した分は「急減」に数えない

- **対応**: #75（2026-10-21 人が決定）
- **章**: §12.4（b）
- **変更内容**: Sakutei が prune で実際に消した orphan（予算と承認を通って Delete が成功したもの）を、planned_change の宣言済み削除と同じく「意図された減少」として扱い、次の周の急減判定で基準の件数から差し引く。差し引くのは、消したと記録した ID のうち次の List に実際に無いものだけ。自分が消していない ID の消失は、引き続き急減として halt する。記録は基準の件数と同じ S3 に置き、失えば差し引かずに判定する（安全側）。
- **理由**: v1 の試用（docs/trial/README.md の D3）で、`--approve-large-change` で 3 件中 2 件を消した直後の周から、自分の削除を急減と見なして prune が止まり、止まった周は基準を更新しないためデーモンを起こし直すまで止まり続けた。急減 halt が守りたいのは「List のサイレント欠損」であり、予算と承認を通った自分の削除はそれに当たらない。planned_change と同じ扱いにすれば、宣言・承認された減少は通し、それ以外は止める、という一つの規律にそろう。

---

## 見送り

- **急減で止まったとき、人が「この件数を新しい基準にする」と承認できる口**: 今回の問題（自分の削除での誤発火）は差し引きで解ける。自分以外の理由での減少は、まず原因を調べるべきもので、基準を付け替える口は運用の要求が出てから考える。今はデーモンの起こし直しで基準が作り直される（S3）。
