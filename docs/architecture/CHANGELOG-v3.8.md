## CHG-01 — v1 の採番はファイル版で確定、SQLite 版は v2 以降

- **対応**: #36
- **章**: §19.9・§27.3・§27.5
- **変更内容**: v1b で「SQLite 版は後で差し替える」としていた記述を、「v1 の採番はファイル版（`FileAuthority`：JSON + flock、fencing 世代つき）で確定し、SQLite 版（または NetBox 等の外部権威）は v1 の範囲に含めず v2 以降に `AllocationAuthority` の別実装として足す」に改めた。§27.3 の v1b 状況表と §27.5（v2 以降）に反映した。§19.9 の SQLite + `BEGIN IMMEDIATE` の記述は、その時点での最小実装の候補として残した。
- **理由**: ファイル版は、同一ホストでの同時払い出しの直列化・二重払い出しの防止・fencing・HA 最小形（§19.8）を満たしており、v1 が実証すべきこと（採番連携による合成リソースの実体化）に足りている。SQLite を入れるにはリポジトリ初の外部依存が要り、v1 の時点でその費用を払う理由がない。差し替えは seam の裏で局所的に済む（§19.9 の規律 (1)）。
