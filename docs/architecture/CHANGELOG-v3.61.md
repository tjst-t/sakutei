## #192：変える chain を通る経路の先は「変えたあとだけ確かめる」（§7.4・§29.1）

- **背景**: `confirm` に、変える対象の chain を通る経路の先（例：境界の FW の forward・DNAT を通る別の経路の ssh）を書くと、
  空からの初回はまだ経路が無いので、変える前の確かめでその先に届かない。そのため一度も変えられなかった。
- **決定**:
  - `confirm` の先ごとに、前に `after:` を書けば**変えたあとだけ確かめる**（`self, after:ssh://admin@192.0.2.20:2200`）。
    印の付いた先は変える前に届かなくても止めない。変えたあとはほかの先と同じに必ず届くことを確かめ、届かなければ巻き戻す。
  - 変える前に確かめる先が 1 つも無い宣言（`self` を外し、全部に印を付けたもの）は**読み込みで断る**。`after:self` と、
    印の有無だけが違う同じ先の二度書きも断る。
  - 同じトランザクションの複数の base chain で同じ先の印が食い違えば、印の無い方（変える前にも確かめる）に寄せる。
  - plan の `confirm` の行には書いたとおり印が出る。前の確かめで止めた知らせ・後の確かめで戻した知らせの
    `Confirm targets:` にも印つきで出す。
  - docs（`docs/providers/nftables.md`・`docs/network-policy.md`）に、この行き詰まりと避け方（印を付ける・初回は `self` だけで
    組んでから先を足す）を書いた。
- **互換**: 印を書かなければ今までどおり。
- **見送り**:
  - 変える前に「届かないこと」を確かめる印（前は閉じ、後は開くの両方を見る）。
  - 確かめる先ごとの時間の上限。
