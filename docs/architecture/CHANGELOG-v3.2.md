# Sakutei 設計書 v3.2 変更一覧（CHANGELOG）

対象: v3.1 → v3.2。改訂日 2026-07-24。骨格（§1〜§29 の機構）は不変。本改訂は**障害駆動の人手対処（human-in-the-loop remediation）の仕組み化**（ADR-0023）を反映する小改訂である。新プリミティブの追加はない。

形式: **変更ID / 対応 / 章 / 変更内容 / 設計判断の理由**。

---

## CHG-H1 — §14.7「障害駆動の人手対処」新設

- **対応**: ADR-0023
- **章**: §14.7（新設）
- **変更内容**: 物理作業（ディスク / ノード / SFP 交換・Vault unseal）が必須の修復を、既存部品の合成（`strategy: task` 起動 + Event/sink 通知 + S2 永続の待ち + 承認ゲート + 観測ゲート）で Workflow として第一級に載せる型を規定。「判断は承認ゲート、物理作業は観測ゲート（ready_condition）」の使い分けと、人間を external_owner と同型に扱う原則（作業指示は出さず、人が変えた現実を Observe して進む＝原則7の人間への適用）を明文化。ディスク交換の推奨形と、§13.4 是正 Workflow・Vault sealed-on-restart（§23）が同型である旨を記載。
- **理由**: 人手対処を Sakutei の外（監視 + ITSM 運用）に置くと、通知・待ち・作業前後の自動段・事実確認・S4 監査が分断される。既存プリミティブの合成だけで載ることが確認できたため、型として固定し v1.5（最小 Workflow）実装の指針とする。

## CHG-H2 — `strategy: task` に 1-outstanding 制約

- **対応**: ADR-0023
- **章**: §6.2
- **変更内容**: `strategy: task` の起動を、同一リソースにつき未完了の Task/Workflow インスタンス高々 1 つに制限。未完了（承認待ち・halt 含む）の間は再起動せず、完了または cancel 後の周期に差分が残っていれば改めて起動する。
- **理由**: level-triggered な収束は同じ差分を毎周期検知し続けるため、抑止がないと手続き・チケットが周期ごとに乱造される。§6.2 は「起動するだけ」までしか規定しておらず、多重起動の扱いが未定義だった。

## CHG-H3 — ゲート timeout のゲート単位宣言

- **対応**: ADR-0023
- **章**: §6.4・§14.4
- **変更内容**: 承認ゲートの timeout を「例 24h」の固定例示から「ゲート単位で宣言可（既定 24h）」に変更。
- **理由**: 部品調達を伴う物理作業の観測ゲートは週単位を要し、24h 固定では人手対処ゲートが常に halt する。

## 見送り

- **新プリミティブ「human task」の追加**: 人手は「判断 = 承認ゲート」「物理作業 = 観測ゲート」に分解でき、既存 2 ゲートで表現できる。コア肥大を避ける（§3 原則5）。
- **人間の Provider 化**（Apply = チケット起票 / Read = 作業結果確認）: 非冪等・経路依存の作業を毎周期の収束ループに載せることになり §6.5 に反する。チケット起票は sink の一実装として扱えば足りる。
- **人手ゲートを含む Workflow への freeze 暗黙強制**: §14.7 では明示の freeze 段を推奨形に留める。暗黙の mode 変更は「どこで freeze されたか」の追跡性を損なう。lint 警告での補助は実装中に決める事項として残す。
