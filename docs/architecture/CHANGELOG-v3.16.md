## CHG-01 — 仮想メディアの ID は `<ノード名>/cd`

- **対応**: #82（#48 の子タスク「仮想メディア」の実装とレビューで決定）
- **章**: §29.1「Redfish の BMC provider」の（2）（6）
- **変更内容**: v3.15 では「システム」と「仮想メディア」の ID をどちらもノード名としていた。これを、**システムの ID はノード名**（provider `redfish-system`）、**仮想メディアの ID は `<ノード名>/cd`**（例 `node1/cd`、provider `redfish-virtual-media`）に改める。BMC は `/cd` の前のノード名で引く。仮想メディアの `name` フィールドにはノード名を書く。`/cd` で終わらない ID はロードの時点でエラーにする。あわせて（6）に、`Inserted` が false なら image を空として比べること、差し替えの Eject → Insert は同じ Apply の中で行うことを書き足した（v3.15 の決まりを明文化しただけで、判断は変えない）。
- **理由**: Local ID は provider をまたいで intent 全体で一意である（loader が重複を拒む〈D-2〉。depends_on の名前でもある）。両方をノード名にすると、同じノードの電源・起動先と CD を並べて宣言できない——CD から起動する手順では両方が要る。ID の一意性を「provider + ID」に広げるのはコア（loader・DAG・収束ループの各所）に波及するので取らず、dnszone の `<FQDN>/<TYPE>` と同じく型を ID の末尾に付ける形にした。CD のドライブは 1 台に 1 つという前提で、末尾は固定の `cd` とする。

---

## 見送り

- **ID の一意性を provider ごとにする**: 同じ形の衝突がほかの provider でも繰り返し起きたら、コアの変更として検討する。
- **CD 以外の仮想メディア（USB・フロッピー）や複数の CD**: 要る BMC が出てから。そのときは末尾（`/cd`）を広げる。
