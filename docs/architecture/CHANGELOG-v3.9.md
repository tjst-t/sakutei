# Sakutei 設計書 v3.9 変更一覧（CHANGELOG）

対象: v3.8 → v3.9。改訂日 2026-10-20。骨格（§1〜§29 の機構）と設計判断（原則・機構）は不変。本改訂は **Sync Mode の git コミット**（Backlog #35）の実装に合わせ、§29.1 の運用パラメータ「Sync Mode の commit 主体」を人の決定どおりに確定し、§24.5 の「v1b の実装」を書き足す小改訂である。

形式: **変更ID / 対応 / 章 / 変更内容 / 設計判断の理由**。対応の `#nn` は Backlog の項目番号。

---

## CHG-01 — Sync Mode の commit 主体：既定 `sakutei-sync`、署名なし

- **対応**: #35
- **章**: §24.5・§29.1
- **変更内容**: Sync のコミットの author・committer を既定 `sakutei-sync <sakutei-sync@localhost>`、署名なしとし、`--committer-name` / `--committer-email` で変えられるようにした。署名は既定でオフで、足すときはコミットを作る 1 か所に鍵を渡す形にする。Sync は自分のコミットを名前でなく trailer `Sakutei-Sync: <scope> <provider>` で見分ける。1 周で書いたスナップショットは 1 つのコミットにまとめ、人がステージしているものは入れない。
- **理由**: commit の attribution はシステムとして明確にする（§26.3）。名前は運用で変えたくなる（拠点ごとの bot 名など）ので、見分けには名前に依らない trailer を使う。署名鍵の配布は資格の局所性（§20）と絡むため、既定では持たない。

## CHG-02 — コミットの間引きを managed 候補と共通化

- **対応**: #35
- **章**: §24.4・§24.5
- **変更内容**: Sync も import と同じく 1 周に `--samples` 回観測し、値が変わったフィールドを managed 候補とする。書き直し（＝コミット）の判定は managed 候補の値を除いた内容のハッシュで行う。一度候補になったフィールドはスナップショットに印を残し、以後の周もその値の変化だけでは書き直さない。
- **理由**: §24.5 の「意味のない差分まで毎周 commit すると監査ログの可読性が下がる」への対処で、§24.4 が「この機構は Sync Mode の commit 間引きと共通化する」としたものの具体化。印をスナップショット（git）に置くので、観測 state を持たない原則（§3）を崩さない。

## CHG-03 — 直接コミットの拒否を git の側にも広げる

- **対応**: #35
- **章**: §9.6・§24.5
- **変更内容**: HEAD のスナップショットが Sync の最後のコミットの内容と違う（人がコミットで変えた）か、Sync が書いたことのないファイルがコミットされているなら、その組は上書きもコミットもせずに止める。戻し方は、Sync の最後のコミットの内容に戻すか、コミットで消すこと。
- **理由**: v3.4 の手編集検知（本文ハッシュ）は、ハッシュを合わせ直した編集や、作業ツリーでなくコミットに入った変更を拾えない。generated/ の「直接コミットを拒否する」規律（§9.6）を、Sync 自身が守る側で実装した。

## 見送り

- **コミットの署名の実装**: 既定オフの決定に従い、今回は口だけ用意した（`--no-gpg-sign` で利用者の git 設定にも引きずられない）。
- **intent 側の sync 設定でコミッターを宣言する書式**: フラグで足りるため見送った。拠点ごとに変えたい要求が出たら `scopes[].sync` に足す。
