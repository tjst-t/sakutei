# Sakutei 設計書 v3.1 変更一覧（CHANGELOG）

対象: v3.0 → v3.1。改訂日 2026-07-22。骨格（§1〜§29 の機構）は v3.0 のまま。本改訂は**位置づけ（§29.4）の確定**のみを行う小改訂である。

形式: **変更ID / 対応 / 章 / 変更内容 / 設計判断の理由**。

---

## CHG-L1 — 位置づけを「OSS 個人プロジェクト第一歩」に確定

- **対応**: 作者の意思決定（当初は社内利用が主目的・OSS 化はボーナスという想定 → OSS 個人プロジェクトが第一歩へ前提転換）
- **章**: §29.4（非技術の着手条件）
- **変更内容**: 「雇用主の IP / OSS 公開規程の確認」を着手前の関門としていた記述を、「OSS 個人プロジェクトを第一歩とする（雇用主 IP 規程の制約は存在しない＝関門クリア済み）」に書き換え。将来の業務利用はありうるが第一歩は OSS と明記。
- **理由**: 位置づけの転換は実装の意思決定に波及する。§29.4 は spec 内で位置づけを述べる唯一の箇所であり、ここを正とすることで設計の正と現実が一致する。

## CHG-L2 — ライセンスを Apache-2.0 に確定

- **対応**: OSS 前提では第一級の着手前判断
- **章**: §29.4
- **変更内容**: 最初のコード公開時点から **Apache-2.0** を適用すると決定。
- **理由**: インフラ／Go／プロバイダ SDK エコシステムの定番（Terraform 系・k8s 系と同一）。特許条項を含むため将来の企業利用でも安心。MIT（特許条項なし）と AGPL-3.0（企業採用障壁が高い）は、SDK による広い採用を狙う本プロジェクトの目標に対し前者は保護不足・後者は過剰と判断し不採用。

## CHG-L3 — 位置づけ転換に伴う 2 つの昇格を明記

- **対応**: CHG-L1 の帰結
- **章**: §29.4
- **変更内容**: OSS 前提により (a) **プロバイダ SDK の公開 API 設計（§28）** が中核目標（ボーナスでなく）に、(b) **段0-minimal（§23.6）** が縮退形でなく OSS 初期利用者の標準の入口になりうる、の 2 点を第一級の設計判断として明記。
- **理由**: 個人 OSS の初期利用者に Proxmox 3ノード + Ceph + Vault-HA の段0 は重い。採用は SDK の作りやすさと入口の軽さで決まる（§28 の「Provider 作成のしやすさが採用を決める」原則の延長）。実装スライス（§27）の優先度づけに影響する。

---

## 見送り

- **段0-minimal を段0 の既定に昇格**（§23）: 本改訂では「入口になりうる」と位置づけるに留め、§23 本文の既定は変更しない。実際の利用者フィードバックが出る前の既定変更は早すぎる（§29.2 の再検討トリガに委ねる）。
- **LICENSE ファイルの追加**: リポジトリはまだ設計仕様のみ（コード未実装）。ライセンスファイルは最初のコード公開時に置く（§29.4 の決定に従う）。
